# PilotACS Deployment Guide

English | [简体中文](./DEPLOYMENT.md)

Build, deployment and acceptance instructions for TR069 ACS (Java Edition). The goal is that a clean machine can be brought up and can accept ONUs by following this document step by step.

---

## 1. Deployment Overview

Everything ships as a single Spring Boot fat-jar; the frontend is packaged into the jar and served by the backend, so Nginx is not required.

| Item | Description |
| --- | --- |
| Admin console | `http://<ip>:8888` (`server.port`, pages live in `BOOT-INF/classes/static` inside the jar) |
| Admin API | Same origin, `/api/**` |
| CPE report | `http://<ip>:9090` (Huawei), `:8012` (ZTE), `:8080` (FiberHome), `:8082`, `:8172`, `:5481`, `:6060` (`acs.cwmp.listen-ports`, add or remove as needed) |
| Database | MySQL 8 / MariaDB 10.6+, database name `tr_acs` |
| Cache / queue | Redis 6+ (report peak shaving and command queue; without Redis the queue can be disabled to run in degraded mode) |
| Work order templates | Jar-external directory `configuration/`; file changes are hot-reloaded, no restart needed |

## 2. Requirements

| Component | Version | Notes |
| --- | --- | --- |
| JDK | **21** | `java.version=21` in `pom.xml`; lower versions will not compile |
| Maven | 3.9+ | Builds the backend |
| Node.js | 18 | Only needed to build the frontend; Node 17+ requires `--openssl-legacy-provider` because of OpenSSL 3 |
| MySQL / MariaDB | 8 / 10.6+ | Character set `utf8mb4` |
| Redis | 6+ | Optional, see section 5 |

## 3. Directory Structure

```
PilotACS/
└── server/
    ├── pom.xml
    ├── sql/schema.sql                 # single database creation script (required for deployment, committed)
    ├── deploy/config/application.yml.example   # external configuration template
    ├── configuration/                 # external configuration root (outside the jar)
    │   └── models/                    # per-model capability tree {isp}/{model-id}.xml (generated by capability tree export)
    └── web/                           # frontend (vue-admin-template); build output dist/ is not committed
```

> `sql/schema.sql` is the **single database creation script for the whole database**: it is executed manually during deployment,
> and the automatic creation of missing tables at application startup also reads from it
> (it is copied into `BOOT-INF/classes/db/schema.sql` inside the jar at build time, and each module picks the statements for its own tables).

> `configuration/` is deliberately not packaged into the jar: adding a new ONU model on site only requires editing files in this directory,
> which take effect immediately via hot reload (800 ms debounce after a file change, plus a 60-second polling fallback).

## 4. First Deployment

### 4.1 Create the database

```sql
CREATE DATABASE tr_acs DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
```

### 4.2 Run the creation script

```bash
mysql -u root -p tr_acs < server/sql/schema.sql
```

The script uses `CREATE TABLE IF NOT EXISTS`, so running it repeatedly is harmless, and it contains **all tables**
(devices, capability trees, intent templates, business templates, model semantic mapping, delivery tasks, northbound webhooks, etc.).

Each module also has an `acs.<module>.auto-create-table` switch (default `true`): it targets the case of "an existing database missing a few tables",
picking the missing ones out of this script at startup and creating them, so no manual steps are needed for those gaps.

A schema self-check also runs at startup: missing core tables print a clear message, and setting `acs.database.fail-on-missing-table=true` aborts startup instead.

### 4.3 Prepare the external configuration

Place `config/application.yml` in the **same directory as the jar**, containing only the keys you want to override
(Spring Boot gives it native precedence over the same keys inside the jar, so no repackaging is needed):

```bash
mkdir -p /opt/pilotacs/config
cp server/deploy/config/application.yml.example /opt/pilotacs/config/application.yml
```

Minimum mandatory changes:

```yaml
spring:
  datasource:
    url: jdbc:mysql://<db-ip>:3306/tr_acs?useUnicode=true&characterEncoding=UTF-8&useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=Asia/Shanghai&rewriteBatchedStatements=true&nullCatalogMeansCurrent=true
    username: root
    password: <on-site password>

acs:
  public-host: <ACS IP>        # connection request address delivered to the ONU; must be the real address
  cwmp:
    listen-ports: 9090,8082,6060,8012,8080,8172,5481   # CPE report ports; listing extra ports is harmless
    # 9090 Huawei / 8012 ZTE / 8080 FiberHome, the rest are common vendor fallbacks
    # Alcatel's usual 8888 collides with server.port (skipped if listed) — move the admin port first
```

You can also skip the file entirely and override via environment variables (native Spring Boot name mapping):

```bash
export SPRING_DATASOURCE_URL='jdbc:mysql://...'
export SPRING_DATASOURCE_PASSWORD='xxx'
export ACS_CWMP_LISTEN_PORTS='9090,8082'
```

> `config/application.yml` contains the database password and is excluded in `.gitignore` — never commit it.

### 4.4 Build

Backend (skipping tests):

```bash
cd pilotacs/server
mvn clean package -DskipTests
```

The frontend must be built separately — `dist/` is not in the repository, and without building it the resulting jar contains no pages:

```bash
cd pilotacs/server/web
npm install --legacy-peer-deps --no-audit --no-fund
npm run build:prod          # on Windows run first: set NODE_OPTIONS=--openssl-legacy-provider
```

You can also let Maven build both in a single command (add `-Dnpm.executable=npm` on Linux/macOS):

```bash
mvn clean package -Pweb -DskipTests
```

Artifact: `server/target/pilotacs-server.jar`.

### 4.5 Deployment directory

```bash
mkdir -p /opt/pilotacs/{config,logs}
cp server/target/pilotacs-server.jar            /opt/pilotacs/
cp -r server/configuration                     /opt/pilotacs/configuration   # work order templates
cp server/deploy/config/application.yml.example /opt/pilotacs/config/application.yml
```

Final layout:

```
/opt/pilotacs/
├── pilotacs-server.jar
├── config/application.yml
├── configuration/          # work order templates, hot-reload directory
└── logs/
```

The template root is resolved against the **process working directory**, and the jar already defaults to `./configuration`,
so starting from `/opt/pilotacs` picks up exactly the directory above with no extra configuration.

Only when starting from another working directory do you need to set it explicitly:

```yaml
acs:
  worklist:
    root-path: /opt/pilotacs/configuration
```

> When the directory is empty, it falls back in order to `configuration/` next to the jar and `target/configuration/`, and sample configuration is extracted automatically.

### 4.6 Start

Foreground (recommended for the first run, easier to read logs):

```bash
cd /opt/pilotacs
java -jar pilotacs-server.jar
```

Background:

```bash
nohup java -jar pilotacs-server.jar > logs/stdout.log 2>&1 &
```

Windows:

```bat
cd /d D:\pilotacs
java -jar pilotacs-server.jar
```

systemd (optional):

```ini
[Unit]
Description=PilotACS ACS Server
After=network.target mysql.service redis.service

[Service]
Type=simple
User=root
WorkingDirectory=/opt/pilotacs
ExecStart=/usr/bin/java -jar /opt/pilotacs/pilotacs-server.jar
Restart=always
RestartSec=10
StandardOutput=append:/opt/pilotacs/logs/stdout.log
StandardError=append:/opt/pilotacs/logs/stdout.log

[Install]
WantedBy=multi-user.target
```

Open the firewall for `8888` (admin), `9090`/`8082` (CPE reports) and `8899` (northbound API, only for partners).

The northbound API having a dedicated port exists exactly for this: allowing upstream systems access does not require exposing the admin console.
If you do not need northbound integration, set `acs.openapi.port` to `0`; `/openapi/v1/**` is then served under 8888 (without port isolation).

## 5. Configuration Reference

| Property | Default | Description |
| --- | --- | --- |
| `server.port` | `8888` | Admin console and frontend port |
| `spring.datasource.*` | local `tr_acs` | Database connection; the connection string character set must be `UTF-8` — `utf8mb4` throws an exception |
| `spring.data.redis.*` | `127.0.0.1:6379` | Queue storage |
| `acs.public-host` | `127.0.0.1` | **Must be changed in production**; the address ACS advertises to the ONU |
| `acs.cwmp.listen-ports` | `9090,8082,6060,8012,8080,8172,5481` | CPE report ports, comma separated; duplicates of the main port are skipped automatically (so Alcatel's 8888 cannot be served) |
| `acs.cwmp.cpe-path` | `/ACS-server/ACS` | Primary CPE report path |
| `acs.cwmp.extra-cpe-paths` | `/acs,/ACS,/cwmp,/CWMP,/tr069,/TR069,/CPE,/cpe,/` | Compatible report paths; append new variants seen on site |
| `acs.auth.cpe-to-acs-username/password` | `hgw/hgw` | Digest credentials the ONU uses to reach the ACS; `auto` or empty disables authentication and accepts any credentials |
| `acs.auth.acs-to-cpe-username/password` | `itms/itms` | Credentials ACS uses for reverse connections to the ONU; also supports `auto` / empty |
| `acs.worklist.root-path` | `./configuration` | External configuration root (`models/`); falls back to `configuration/` next to the jar when empty |
| `acs.queue.enabled` | `true` | Disable to fall back to in-process synchronous handling, the degraded option without Redis |
| `acs.biz.auto-create-table` | `true` | Auto-creates business template tables |
| `acs.database.fail-on-missing-table` | `false` | Whether startup aborts when tables are missing |
| `admin.jwt.expire-hours` | `12` | Admin token lifetime (hours) |

> The admin JWT signing key is not in any configuration file: `JwtSecretProvider` loads it from `target/secret.xml`
> under the process working directory and generates it automatically on first start — **that file must be included in backups**
> (if lost, all issued tokens become invalid; for multi-instance deployments, place the same file in the working directory of every instance).
> The initial administrator account is inserted by `sql/schema.sql` when the database is created and is no longer configured through files.

## 6. Acceptance Checklist

The startup log should show, in order:

1. `Started PilotAcsApplication in X seconds`
2. `CPE 上报路径：主路径 /ACS-server/ACS，兼容 [...]` — the path compatibility list is in effect
3. `CPE 上报监听端口：[8888, 9090, 8082]（主端口 8888，额外 [9090, 8082]）`
4. No `数据库自检失败` / no missing-table messages
5. On first deployment one warning appears: `sys_user 为空，已创建初始管理员 [admin]，请登录后立即修改密码`

Then:

```bash
# Admin console page
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8888/          # 200

# Report port: an empty POST should no longer return 405
curl -s -o /dev/null -w "%{http_code}\n" -X POST http://127.0.0.1:9090/  # 400 or 204, must not be 405
```

Open `http://<ip>:8888` in a browser and log in with `admin/admin` (change the password immediately after first login).

API-level self-check (if results are unexpected, follow [`API.md`](../API.md) §7 for troubleshooting):

```bash
TOKEN=$(curl -s -X POST http://127.0.0.1:8888/api/user/login \
  -H 'Content-Type: application/json' -d '{"username":"admin","password":"<pwd>"}' \
  | sed -n 's/.*"token":"\([^"]*\)".*/\1/p')

curl -s http://127.0.0.1:8888/api/dashboard/overview -H "X-Token: $TOKEN"   # code=200
curl -s http://127.0.0.1:8899/openapi/v1/devices?size=1 -H "X-Token: $TOKEN" # code=200

# Port isolation: admin paths on 8899 must return 404
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8899/api/dashboard/overview  # 404
```

CPE report acceptance is covered in the next section.

## 7. Onboarding ONUs

On the ONU side, fill in the ACS URL (9090 as an example):

```
http://<ACS IP>:9090/
```

Fill in `hgw/hgw` as the ACS authentication credentials (or the actual on-site values, matching `acs.auth.cpe-to-acs-*`).

Normal interaction flow:

1. The ONU sends the first Inform (no auth header) → ACS replies **401 + `WWW-Authenticate`**, and the log prints `等待设备携带认证重发 Inform: sn=xxx`
2. The ONU resends with digest → validation passes, ACS replies 200 + InformResponse, and the device is written into `cpe_device`
3. Afterwards the ONU periodically sends empty POST probes, and ACS piggybacks commands onto them when there is anything pending

## 8. Troubleshooting

| Symptom | Cause | Action |
| --- | --- | --- |
| The ONU keeps reporting but ACS receives nothing; log shows `Request method 'POST' is not supported` / response `Allow: GET, HEAD` | The report path configured on the ONU is not in the list, so the request is swallowed by the static resource handler (405) | The log prints `收到未匹配的上报请求：端口 xxx 路径 /yyy`; add `/yyy` to `acs.cwmp.extra-cpe-paths` and restart |
| Constant `401`, log shows `设备认证失败: sn=xxx` | The ACS account on the ONU does not match `acs.auth.cpe-to-acs-*` | Change the ONU account to `hgw/hgw`, or change the configuration to match the ONU; note that the ONU service account (LOID) and the ACS authentication account are two different things |
| Startup reports missing tables | `sql/schema.sql` was not executed | Run the script and restart |
| Page 404 / blank screen | The frontend was not built, so the jar has no `static` | Run `npm run build:prod` or `mvn -Pweb` first, then `mvn package` |
| Template list is empty | There is no `configuration/` under the working directory and none under the fallback paths either | Copy `server/configuration` to the working directory, or set `acs.worklist.root-path` explicitly |
| Connection string reports `Unsupported character encoding` | `characterEncoding` was set to `utf8mb4` | Change it to `UTF-8` |
| Database connection failure right at startup | Database not created / wrong credentials / network unreachable | First verify manually with `mysql -h ... -u ... -p tr_acs` |
| Redis unreachable | Redis is not deployed | Install Redis, or set `acs.queue.enabled=false` to degrade (failed enqueue is handled locally) |

## 9. Upgrade and Backup

Upgrade: back up configuration and templates → stop the process → replace the jar → start.

```bash
cp -r /opt/pilotacs/config /opt/pilotacs/config.bak
cp -r /opt/pilotacs/configuration /opt/pilotacs/configuration.bak
# stop the process, replace the jar, then start again
```

- Configuration files and the template directory both live outside the jar, so replacing the jar does not overwrite them
- Missing tables are created automatically from `sql/schema.sql`, so upgrades generally need no manual SQL
- When `sql/schema.sql` gains new tables, you can run it again on site (the script is idempotent) or simply rely on auto-creation
- Back up the database regularly: `mysqldump -u root -p tr_acs > tr_acs_$(date +%F).sql`

## 10. Pre-Production Checklist

- [ ] Change `acs.public-host` to the real IP, otherwise the connection request address delivered to the ONU is `127.0.0.1`
- [ ] Confirm `target/secret.xml` has been generated and is included in backups (JWT key; multiple instances must share the same file)
- [ ] Keep database credentials out of the repository (the external `config/application.yml` is already git-ignored)
- [ ] Change the initial administrator password after login
- [ ] `configuration/` (templates and ONU adaptation) is in place under the working directory
- [ ] Firewall opened for 8888 / 9090 / 8082 (admin and reports), 8899 as needed for northbound
- [ ] Northbound integration: confirm the caller's token can call `/openapi/v1/devices`, the callback URL is reachable and its `secret` is configured (needed to compute the event signature)
- [ ] The `root_node` of the model profile matches the root node reported by the device: when one model has both TR-098 and TR-181 firmware,
      you must create one adaptation for each (delivery reconciles them beforehand and is rejected outright on mismatch)
